# Week 6 Observation

## Task 1

동일한 비용의 최단 경로가 있으면 이웃 노드를 정렬해 먼저 탐색되는 경로를 선택했다.
u에서 w까지는 직접 연결 비용 5보다 u-x-y-w의 비용 3이 짧으므로 next hop은 w가 아니라 x이다.
u-x 링크가 끊어지면 w, y, z로 가는 경로가 우회되어 next hop이 변경된다.

## Task 2

국내 traceroute에서는 61.253.30.129 부근부터 외부 ISP 경로로 나가는 것으로 보였고, 일부 `*`는 응답 차단 또는 시간 초과를 뜻한다.
OSPF에서 r1-r2 링크를 차단한 뒤 재수렴 시간은 약 3초였으며, hello/dead interval 동안 장애를 감지한 뒤 우회 경로를 계산하기 때문이다.
링크 복구와 비용 변경은 새 이웃·LSA를 학습하는 과정이 필요하지만, 비용 변경은 장애 감지를 기다리지 않아 링크 장애보다 빠르게 수렴한다.

## Task 3

YourRouter는 최단 경로에 실제로 사용되는 링크를 기억하고, 사용하지 않는 링크 장애에는 전체 SPF를 다시 계산하지 않았다.
모든 이벤트 후 테이블은 정확했으며 SPF 실행 횟수를 1001회에서 716회로 줄여 약 28%를 절감했다.
추가 자료구조 때문에 Python wall time은 느릴 수 있지만, 실제 라우터에서는 CPU 사용량과 전체 SPF 재계산 횟수를 줄이는 것이 더 중요하다.
