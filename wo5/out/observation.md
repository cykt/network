# W05 observation

## Task 1
`/31`과 `/32`는 일반적인 의미의 usable host가 없으므로 first와 last를 `None`으로 처리했다.
`10.20.30.70`은 `/8`, `/16`, `/24`, `/26` 네 경로에 모두 포함되며, 가장 긴 prefix인 `/26`의 next hop을 선택했다.
같은 prefix 길이의 경로가 중복되면 먼저 추가된 항목을 유지하도록 구현했다.

## Task 2
로컬 주소 `192.168.35.195`는 사설 주소이고 외부에서 보인 `61.253.30.184`와 다르므로 최소 한 단계의 NAT가 존재한다.
현재 두 기록의 주소가 같아 실제로 다른 네트워크로 전환되었는지는 추가 확인이 필요하며, 두 번째 네트워크에서는 새로 수집해야 한다.
DHCP Discover는 아직 주소가 없으므로 source `0.0.0.0`, destination `255.255.255.255`로 broadcast된다.

## Task 3
prefix length별 dictionary를 사용하여 라우트를 33개 그룹(`/0`~`/32`)으로 저장했으며, 각 그룹에서 같은 네트워크의 첫 next hop을 유지했다.
조회는 `/32`부터 `/0`까지 최대 33개의 prefix 길이만 확인하므로 전체 라우트 수가 아니라 prefix 길이 수에 비례한다.
Python에서는 dictionary 방식이 빠르지만, 하드웨어 라우터는 메모리 사용량을 감수하고 주소 비트를 따라가는 trie를 사용해 일정한 깊이로 조회한다.
