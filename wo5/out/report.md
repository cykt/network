# W05 Task 2 보고서: 주소와 DHCP

## A. 현재 주소 분석

### Campus Wi-Fi

- IPv4 주소: `192.168.35.195`
- 서브넷 마스크: `255.255.255.0` (`/24`)
- 네트워크 주소: `192.168.35.0`
- 네트워크 범위: `192.168.35.0` ~ `192.168.35.255`
- 사용 가능한 호스트 범위: `192.168.35.1` ~ `192.168.35.254`
- 기본 게이트웨이: `192.168.35.1`
- 공인 IPv4 주소: `61.253.30.184`

게이트웨이 `192.168.35.1`은 `192.168.35.0/24` 안에 있으므로 같은
서브넷에 있다. 따라서 호스트는 게이트웨이로 직접 이더넷 프레임을
전달할 수 있다.

`192.168.35.195`는 RFC 1918 사설 주소이고, 외부에서 관찰된
`61.253.30.184`는 공인 주소이다. 두 주소가 다르므로 로컬 네트워크와
인터넷 사이에 최소 한 단계의 NAT가 있다.

### Phone tethering

현재 `addresses.json`의 두 번째 기록도 실제 Wi-Fi 인터페이스가 다음과
같이 기록되어 있다.

- IPv4 주소: `192.168.35.195`
- 서브넷 마스크: `255.255.255.0` (`/24`)
- 기본 게이트웨이: `192.168.35.1`
- 공인 IPv4 주소: `61.253.30.184`

두 기록의 주소가 완전히 같으므로, 두 번째 측정 시점에는 실제로 다른
네트워크로 전환되지 않았거나 기존 Wi-Fi 연결이 계속 사용된 것으로
보인다. 따라서 이 기록만으로는 두 네트워크의 차이를 증명할 수 없다.
휴대폰 테더링에 연결한 뒤 다시 `--collect`를 실행하여 두 번째 기록을
갱신해야 한다.

## B. NAT 관찰

로컬 주소 `192.168.35.195`는 사설 주소이며 외부 주소는
`61.253.30.184`이다. 따라서 적어도 한 번 NAT가 수행된다.

두 단계 NAT 여부는 다음과 같이 판단할 수 있다. 컴퓨터가 받은 주소가
`100.64.0.0/10` 범위라면 통신사 CGNAT까지 사용 중일 가능성이 높다.
현재 주소는 `192.168.35.195`이므로 이 기록만으로는 한 단계 NAT와
추가적인 상위 NAT를 구분할 수 없다.

## C. DHCP 캡처 분석

캡처 파일은 `out/dhcp.pcapng`에 저장했다. Wireshark에서
`dhcp || bootp` 표시 필터를 사용해 다음 네 메시지가 모두 포함되어
있는지 확인해야 한다.

1. Discover
2. Offer
3. Request
4. ACK

Discover의 일반적인 IPv4 주소는 다음과 같다.

- Source: `0.0.0.0`
- Destination: `255.255.255.255`

클라이언트는 Discover를 보낼 때 아직 IP 주소를 할당받지 않았고 DHCP
서버의 주소도 모르기 때문에 source로 `0.0.0.0`을 사용하고 모든 호스트가
받을 수 있는 broadcast 주소로 전송한다.

Wireshark의 DHCP ACK 패킷에서 다음 값을 확인해 이 표를 완성한다.

| 항목 | 캡처에서 확인한 값 |
|---|---|
| 할당된 IP 주소 | `[ACK의 Your IP address 입력]` |
| DHCP 서버 주소 | `[DHCP Server Identifier 입력]` |
| Lease time | `[IP Address Lease Time 입력]초` |

ACK 시점에는 클라이언트가 사용할 IP 주소와 DHCP 서버를 알고 있으므로
ACK는 Discover처럼 반드시 broadcast일 필요가 없다. Lease time의 절반이
되면 클라이언트는 일반적으로 DHCP 서버에 lease 연장을 요청한다.
